## 第一章 引言

### 1.1 项目背景

目前在店内的报修流程管理上仍依赖电话沟通和微信聊天记录进行信息传递，存在以下突出问题：

- **漏单频发**：聊天消息淹没在群聊中，报修信息无统一入口，容易遗漏或遗忘。
- **责任扯皮**：缺乏明确的状态记录和时间戳，报修人与管理员对"谁说了什么、什么时候说的"各执一词。
- **效率低下**：报修人无法实时了解维修进度，需反复询问；管理员也难以批量管理和追踪工单。
- **数据沉淀缺失**：历史报修记录分散在多个聊天窗口中，无法检索、统计和导出，不利于运营分析。

基于以上痛点，本系统旨在将报修流程从线下沟通迁移至线上平台，实现**报修—审核—接单—处理—完工—反馈**的全流程闭环管理。

### 1.2 项目目标

| 目标维度 | 具体描述 |
|----------|----------|
| **流程线上化** | 报修人通过公众号/小程序在线提交报修单，无需电话或微信沟通 |
| **状态透明化** | 工单状态实时可查，每一步操作留痕，形成完整时间轴 |
| **沟通成本最小化** | 关键节点自动推送通知，减少人工反复确认 |
| **数据可追溯** | 所有操作记录持久化存储，支持导出和审计 |
| **角色专业化** | 明确单位审核员、维修业务员等角色职责，提高处理效率 |

### 1.3 术语定义

| 术语 | 定义 |
|------|------|
| **工单（报修单）** | 报修人提交的一条维修请求记录，包含项目大类、项目属性、描述、图片、紧急程度等信息 |
| **草稿** | 报修人已填写但尚未提交的工单状态，可随时编辑和删除 |
| **已上报** | 工单已正式提交，进入本单位单位审核员审核队列，报修人不可再修改 |
| **待接单** | 单位审核员审核通过、上报给维修业务员后的状态，等待维修业务员接单 |
| **处理中** | 维修业务员已接单并开始维修，可更新处理进度、上传维修过程图片 |
| **已处理** | 维修已完成：维修业务员登记维修内容与费用、上传收据作为完工凭证，工单进入终态（可被"重新打开"） |
| **退回** | 单位审核员（已上报）或维修业务员（待接单/处理中）将工单退回，工单状态回到草稿，必须填写退回原因（不少于10字） |
| **取消** | 报修人在草稿/已上报/待接单状态下取消工单，工单进入终态"已取消"，在列表中单独展示 |
| **全局用户角色** | 系统定义的用户平台权限（users.role）：0=普通用户 / 1=维修业务员 / 2=超级管理员，决定端与基础功能访问权限 |
| **单位（企业）内成员身份** | 用户在特定单位内的身份标识（memberships.role）：0=普通成员 / 1=单位审核员，决定在该单位内的操作权限；一个用户可加入多个单位 |
| **单位审核员** | 单位内成员身份（memberships.role=1，可多人），负责审批本单位成员加入、审核本单位工单（通过→待接单/退回），可查看本单位全部工单与汇总统计 |
| **维修业务员** | 店方维修人员（全局角色 users.role=1，原"平台管理员"），负责接单、处理、完工工单，上传收据并登记维修费用，查看个人已接业务与汇总 |
| **普通成员** | 单位内成员身份（memberships.role=0），仅能提交和查看自己的工单 |
| **邀请码/二维码** | 单位创建后生成的唯一标识，用于成员加入单位的凭证，支持刷新有效期 |
| **项目大类** | 维修项目的一级分类（如"电脑维修"），由超级管理员维护，可配置项目属性与常见问题 |
| **项目属性** | 隶属于项目大类的细分属性（如"台式机/笔记本"），报修时必选；每个大类可配置多条属性 |
| **常见问题** | 隶属于项目大类的常见故障条目（含常见解决建议），报修人选择后自动填充报修描述（快捷输入），不随工单持久化 |
| **项目字典** | 项目大类/项目属性/常见问题的合称，存储于数据库（project_categories / project_properties / project_problems），支持软删除与排序 |
| **WebSocket** | 一种全双工通信协议，用于管理后台实时接收新工单提醒 |

## 第二章 项目范围与角色定义

### 2.1 业务范围

#### ✅ 本系统包含

| 模块 | 说明 |
|------|------|
| 单位成员管理 | 单位创建、邀请码/二维码生成与刷新、成员加入/审批/移除、免审核开关 |
| 报修工单流转 | 工单创建、提交、审核、接单、处理、完工、退回、取消、重新打开、通知推送 |
| 单位审核员管理 | 工单审核、退回、工单管理、汇总统计 |
| 维修业务员管理 | 工单接单、处理、完工、收据与费用登记、个人业务汇总 |
| 项目字典管理 | 项目大类/项目属性/常见问题的增删改查（超级管理员专属，数据库存储，软删除+排序） |
| 财务对账 | 维修费用登记与结算对账：完工时登记数量、单价（金额自动计算）及维修内容，上传收据作为完工凭证，支持按企业、按维修业务员导出账单（即导出模式 enterprise/repairer） |

#### ❌ 本系统不包含

| 排除项 | 说明 |
|--------|------|
| 库存管理 | 不涉及维修配件出入库、库存预警 |
| 客户CRM | 不涉及客户关系管理、营销推送 |
| 员工绩效 | 不涉及维修人员工时统计、绩效考核 |

> ⚠️ **边界声明**：以上排除项不在本期项目范围内。如甲方后期需要扩展，应作为新需求单独评估范围、工期和费用。

### 2.2 用户角色

角色体系采用**双层模型**：`users.role`（全局角色）决定端与基础权限，`memberships.role`（单位内成员身份）决定在具体单位内的操作权限；一个用户可加入多个单位。

**全局角色（users.role）：**

| 角色 | 权限说明 | 使用端 |
|------|----------|--------|
| **普通用户 (role=0)** | ① 报修人：提交报修单（新建/草稿/提交），须先加入单位成为成员<br>② 查看自己提交的工单进度<br>③ 接收工单状态变更通知<br>④ 查看维修结果、费用与收据 | 微信公众号 / 小程序 |
| **维修业务员 (role=1)** | ① 店方维修人员（原"平台管理员"）<br>② 处理业务范围内的工单：接单/处理/完工/退回，上传收据并登记维修费用<br>③ Web 后台按单位查看与筛选工单<br>④ 查看个人已接业务并汇总 | Web 管理后台 / 小程序 |
| **超级管理员 (role=2)** | ① 拥有维修业务员全部权限<br>② 查看所有用户列表（搜索/筛选）<br>③ 修改用户属性（昵称/角色/手机号）<br>④ 重置管理员登录密码<br>⑤ 管理项目字典（项目大类/项目属性/常见问题的增删改查） | Web 管理后台 |

**单位内成员身份（memberships.role）：**

| 成员身份 | 权限说明 | 使用端 |
|----------|----------|--------|
| **普通成员 (role=0)** | ① 提交报修单（新建/草稿/提交）<br>② 查看自己提交的工单进度<br>③ 接收工单状态变更通知 | 小程序端 |
| **单位审核员 (role=1)** | ① 审核本单位工单（通过→待接单 / 退回）<br>② 查看本单位所有工单与汇总统计<br>③ 审核本单位成员加入申请（可开启免审核）<br>④ 决定是否上报给维修业务员 | 小程序端 / Web 管理后台 |

## 第三章 功能性需求

### 3.1 企业管理模块

> 说明：本说明书"企业"与"单位"同义（对应数据库 enterprises 表），指创建邀请码/二维码、审核并管理成员报修的客户组织。

#### 3.1.1 创建企业

- **功能描述** : 维修业务员/超级管理员在 Web 管理后台创建单位（企业），系统自动生成唯一邀请码和对应二维码（二维码内容为加入单位的链接）
- **输入** : 单位名称（必填，2-50字符）
- **输出** : 动态二维码
- **业务规则** :
  + 一个单位仅由店方后台创建，同一单位名称不可重复

#### 3.1.2 加入企业

- **功能描述** : 用户扫描单位二维码/输入邀请码提交加入申请，审核通过后生效
- **输入** : 邀请码（扫码自动填充）、用户昵称（取微信昵称）、手机号（选填）
- **输出** : 申请提交成功提示；审核通过后用户成为该单位成员
- **业务规则** :
  + 单位审核员可开启"免审核"模式，用户扫码直接加入
  + 审核模式下，由单位审核员批量通过/拒绝（首批成员可由 Web 管理后台创建单位时一并指定）
  + 一个用户可加入多个单位，切换单位后在对应单位下报修


#### 3.1.3 移除成员

- **功能描述** : 单位审核员可将成员从本单位移除（Web 管理后台亦可操作）
- **输入** : 选择目标成员 → 确认移除
- **输出** : 移除成功提示
- **业务规则** :
  + 移除后该成员不可再提交报修
  + 该成员的历史报修记录保留，不删除
  + 移除操作记录日志（操作人、操作时间、被移除人）


#### 3.1.4 成员列表管理

- **功能描述** : 单位审核员可查看本单位内所有成员列表，支持搜索和筛选
- **输入** : 搜索关键词（昵称/手机号）
- **输出** : 成员列表（昵称、加入时间、报修数量、成员身份）
- **业务规则** :
  + 支持按加入时间、报修数量排序
  + 可查看/调整成员身份（普通成员 ↔ 单位审核员）

### 3.2 报修工单模块

#### 3.2.1 新建工单 / 草稿

- **功能描述** : 报修人（单位普通成员/单位审核员）填写报修信息，可选择保存为草稿或直接提交
- **输入** :
  + 项目大类（下拉选择，必填，数据来自项目字典）
  + 项目属性（下拉选择，必填，仅展示所选大类的属性）
  + 常见问题（下拉选择，选填；选中后自动填充报修描述并可继续编辑——属快捷输入，不随工单持久化）
  + 报修描述（文本，必填，不超过500字）
  + 故障图片（选填，最多9张，jpg/png/webp，单张≤5MB）
- **输出** : 草稿保存成功，工单状态为"草稿"
- **业务规则** :
  + 草稿可多次编辑、可删除
  + 项目大类/项目属性/常见问题由超级管理员维护，存储于数据库字典表（project_categories / project_properties / project_problems），采用软删除+排序，修改即时生效
  + 每个项目大类可关联多个项目属性与多条常见问题（一对多）；工单提交时保存项目大类与项目属性（含名称快照），常见问题不入库
  + 取消"项目名称"字段，改为"项目大类+项目属性"组合（常见问题仅作描述快捷输入）

#### 3.2.2 提交上报

- **功能描述** : 报修人将草稿工单正式提交，工单进入本单位审核队列
- **输入** : 草稿工单ID
- **输出** : 工单状态变更为"已上报"并生成工单号；触发单位审核员/维修业务员实时提醒
- **业务规则** :
  + 提交前校验必填项（项目大类、项目属性、报修描述）及字数/图片规范
  + 提交后报修人不可修改工单内容
  + 提交时记录提交时间戳、生成工单号

#### 3.2.3 查看工单列表（用户端）

- **功能描述** : 报修人查看自己提交的所有工单列表
- **输入** : 状态筛选（全部/草稿/已上报/待接单/处理中/已处理/已退回）；支持按项目大类、紧急程度、时间范围、关键字（工单号/描述）筛选
- **输出** : 工单列表（工单号、项目大类、项目属性、描述摘要、状态、提交时间；已处理工单展示费用金额）
- **业务规则** :
  + 仅展示当前用户提交的工单，不展示他人工单
  + "已退回"为派生筛选项：指曾被退回、当前处于草稿状态的工单
  + 已取消的工单单独展示在列表底部
  + 支持分页查询，每页最多20条，可自定义每页显示数量

#### 3.2.4 查看工单详情（用户端）

- **功能描述** : 报修人查看单个工单的完整信息及处理时间轴
- **输入** : 工单ID
- **输出** : 工单完整信息 + 操作时间轴日志
- **业务规则** :
  + 时间轴记录所有状态变更（操作人、操作时间、操作类型、备注）

### 3.3 工单处理模块（管理后台）

#### 3.3.1 工单列表

- **功能描述** : Web 管理后台展示维修业务员/超管可见范围内的报修工单，支持多维度筛选和排序
- **输入** : 筛选条件（单位、状态、项目大类、紧急程度、时间范围、报修人、维修业务员）
- **输出** : 工单列表（工单号、单位名称、报修人、项目大类、项目属性、描述摘要、状态、提交时间、费用金额；可含接单人、审核人）
- **业务规则** :
  + 默认按提交时间倒序排列
  + 紧急工单在列表中高亮标识
  + 支持分页，每页20条，可自定义每页显示数量
  + 按单位查询功能必须有效，不能显示全部工单（数据隔离）
  + 已取消的工单单独放在列表底部
  + "已退回"作为派生筛选（曾被退回且当前为草稿的工单）


#### 3.3.2 状态流转

工单状态流转规则如下表所示：

| 当前状态 | 可执行操作 | 目标状态 | 触发条件 / 约束 |
|----------|-----------|----------|-----------------|
| 草稿 | 提交 | 已上报 | 表单必填项（项目大类、项目属性、描述）全部完成 |
| 已上报 | 审核通过 | 待接单 | 单位审核员确认工单有效，上报给维修业务员 |
| 已上报 | 退回 | 草稿 | 单位审核员退回，必须填写退回原因（不少于10字） |
| 待接单 | 接单维修 | 处理中 | 维修业务员确认接单，开始处理 |
| 待接单 | 退回 | 草稿 | 维修业务员退回，必须填写退回原因（不少于10字） |
| 处理中 | 完工 | 已处理 | 维修业务员确认维修完成，可同时上传收据图片 |
| 处理中 | 退回 | 草稿 | 维修业务员退回，必须填写退回原因（不少于10字） |
| 已处理 | 重新打开 | 处理中 | 维修业务员可重新打开已处理的工单继续处理 |

**状态流转约束：**

- 每次状态变更均记录操作日志（操作人、操作时间、原状态、目标状态、备注），操作人记录昵称+身份（报修人/单位审核员/维修业务员）。
- "退回"按当前环节执行：已上报由单位审核员退回；待接单/处理中由维修业务员退回；均须填写退回原因（不少于10字）。
- "退回"后工单回到草稿状态，报修人可修改后重新提交；退回原因随工单保留，供"已退回"筛选展示。
- 报修人可在"草稿/已上报/待接单"状态取消工单（取消为终态"已取消"，单独展示）；终态（已处理/已取消）不可再流转。
- 已处理工单可由维修业务员"重新打开"回到处理中继续维修，重新完工时再次登记维修内容与费用。
- 状态流转不支持跳级（如"已上报"不能直接变为"已处理"）。

**状态流转图（文字版）：**

```
草稿 ──提交(校验必填)──→ 已上报 ──审核通过(单位审核员)──→ 待接单 ──接单(维修业务员)──→ 处理中 ──完工(登记费用+收据)──→ 已处理
 ↑退回/取消            ↑退回                     ↑退回                 ↑退回                 ↑重新打开(维修业务员)

退回执行人：已上报→单位审核员；待接单/处理中→维修业务员（均需填写原因≥10字）
取消发起人：报修人（仅草稿/已上报/待接单可取消，取消为终态，单独展示）
```

#### 3.3.3 工单详情（管理后台）

- **功能描述** : 维修业务员/超级管理员查看工单完整信息，执行状态流转操作
- **输入** : 工单ID
- **输出** : 工单完整信息 + 操作时间轴 + 操作按钮区
- **业务规则** :
  + 操作按钮按 3.3.2 状态流转表动态展示（如"已上报"展示"审核通过/退回"，"待接单"展示"接单/退回"，"处理中"展示"完工/退回"，"已处理"展示"重新打开"）
  + 详情页展示项目大类/属性、描述、图片、紧急程度、审核人、接单人、费用与收据、完整操作时间轴

#### 3.3.4 完工与费用登记（含上传收据）

- **功能描述** : 维修业务员确认维修完成并登记费用，上传收据作为完工凭证
- **输入** : 维修内容（必填，≤500字）、数量（默认1）、单价（元，≥0）、扩展信息（维修结果/维修方式/保修期/维修时长，选填）、收据图片（1-3张，jpg/png，单张≤5MB）
- **输出** : 工单状态变更为"已处理"；金额由系统按数量×单价自动计算；收据图片关联至工单，报修人可在工单详情查看费用与收据
- **业务规则** :
  + 金额为数据库生成列（数量×单价），只读展示，不允许手工改写；对账信息可在完工后修改（重新登记），记录修改日志
  + 完工后工单不可再修改；维修业务员可通过"重新打开"回到处理中继续维修，再次完工时重新登记
  + 收据图片在完工后仍可补充上传
  + 已上传的收据图片可替换但不可删除（替换后旧图保留留痕）
  + 完工操作与费用登记均记录操作日志

#### 3.3.5 工单导出

- **功能描述** : 维修业务员/单位审核员可将符合条件的工单导出为 Excel 账单
- **输入** : 导出模式（enterprise=单位（企业对账）账单 / repairer=业务员汇总）、导出范围（全部/按筛选条件/按时间范围，账单类模式需指定时间范围）
- **输出** : Excel 文件（.xlsx）：企业对账单按单位归集（含数量/单价/金额/维修内容/完工时间等，字段见 5.2.1）；业务员汇总按单位分组并输出小计（接单数/完工数/金额等）
- **业务规则** :
  + 两种模式均支持自定义导出列
  + 无匹配数据时返回明确的业务错误，不生成空表（前端需正确解析导出错误响应）
  + 导出操作记录审计日志（操作人、时间、范围）

- **通知内容** : 工单号、单位名称、报修人、项目大类、项目属性、描述摘要、提交时间
- **业务规则** :
  + 对于每个新工单、每个接收人仅发送一条通知
