> **V1.3 关键产品决策记录**（与甲方 2026-09-07 确认）：
> 1. **业务员（role=1）服务主页入口**：默认展示「处理工单」「企业管理」；若同时在某单位担任审核员（membership.role=reviewer）→ 加显「审核工单」；若同时是某单位 approved 成员 → 加显「我的工单」。
> 2. **状态分组口径**（审核页，处理页同口径）：待审核=`reported`；处理中=`pending_accept,processing`；结束=`completed,cancelled`。
> 3. **分类字段映射**：「设备类型」=项目大类（category_id），「问题类别」=项目属性（property_id），**移入①「发生了什么」并置于「添加照片」之前，二者同一行对半分（各 50%）**；**常见问题不作为独立表单项与工单字段**，仅作描述快捷**追加**填充；紧急程度保留在③「帮我们分类」。
> 4. **报修单位保留**，放在「② 在哪里」区块；仅一个可选单位时自动选中。
> 5. **超级管理员（role=2）服务主页四项入口全部展示**（我的工单 / 处理工单 / 审核工单 / 企业管理）。
> 6. 常见问题数据源：未选大类属性时展示"通用常见问题"（**后端接口待提供，本期该区域可留空**）；选中大类 + 属性后自动拉取该属性下的常见问题，展示在描述框下方；用户点击后**以追加方式**写入描述（不整体替换）。
> 7. **单位管理员「查询本单位业务及汇总」口径（2026-09-09 与甲方确认，C20）**：落地为小程序「审核工单」页**「统计」Tab**（同页切换）。时间范围默认**本月**，快捷项 本月/本季/全部 + 自定义起止；计入六种正式状态（reported/pending_accept/processing/completed/cancelled/rejected），**草稿不计**；按 `submitted_at`（最新一次正式提交时间）归入范围；报修人 Top5 按**提交账号昵称**；状态/大类分布用**轻量占比条**（不引入图表库）；无下钻；**Excel 导出二期**。选「全部企业」时：店方/超管可全域聚合；单位审核员需选定具体单位（后端多单位聚合未支持前，同第十一章 #4 过渡限制）。
> 8. **「统计」页改版口径（2026-09-09 与甲方确认，C21）**：审核页 Tab 顺序 = **统计 / 待审核 / 处理中 / 结束**，**默认选中「统计」**。统计页自上而下：① **今日概况卡**（指标 = 当前待审核(reported 存量) / 今日新增上报(submitted_at∈今日) / 今日审核通过(audit 动作今日) / 今日退回(reject 动作今日)；随企业筛选联动、**不随时间范围变化**）→ ② 原 时间范围(默认本月) + 总单数 + 状态/大类分布 + 报修人 Top5（真实头像，空回退首字）不变。「今日」按服务器本地日 0 点 ~ 次日 0 点计，口径与后端 5.17 `data.today` 一致。
> 9. **统计区 UI 版式（2026-09-09 与甲方确认，C22）**：两段独立卡 = 「今日概况」（**标签在左、数值在右**的普通排布，非大数字在上）+ 「历史统计」大卡。历史统计卡内顺序：**时间范围选择 → 总工单数（字段在前、数值在后，普通字号）→ 「状态 / 大类 / 报修人排行」指标胶囊 Tab**（每次只展示当前一项，切换数据同源不重新请求）；总单数旁保留「时间范围 · 更新时间」小字。原 总览/时间范围/状态分布/大类分布/报修人 五张独立卡合并为该大卡内分区。不使用"大数字在前、字段在后"的仪表盘样式。

## 第一章 全局约定（V1.3 更新点）

### 1.1 角色与身份判定

沿用 V1.2 1.1 的双层模型（`utils/auth.ts`：`platformRole()` / `isStoreStaff()` / `isSuperAdmin()` / `reviewerEnterprises()` / `isUnitReviewer()` / `isReviewerOf(id)`，此处不再重复）。

**V1.3 新增：服务主页入口可见性判定 `serviceEntryVisibility()`**（见第三章 3.2 矩阵）：

```typescript
// utils/auth.ts（V1.3 新增）
import { platformRole, isUnitReviewer } from '@/utils/auth'
import { useUserStore } from '@/stores/user'

/** 服务主页「工作服务」入口可见性矩阵 */
export function serviceEntryVisibility() {
  const role = platformRole()                       // 0 普通用户 / 1 业务员 / 2 超管
  const reviewer = isUnitReviewer()                 // 是否担任任一单位审核员
  const memberOfAny = (useUserStore().userInfo?.enterprises ?? [])
    .some(e => e.status === 'approved')            // 是否为任一单位已通过成员
  return {
    myOrders:    role === 0 || role === 2 || (role === 1 && memberOfAny),
    reviewOrders: role === 2 || reviewer,
    repairOrders: role >= 1,
    enterprise:  role >= 1 || reviewer,
  }
}
```

### 5.2 企业筛选 Header

- 「处理中 / 结束」Tab 的卡片按 `available_actions` 显示对应按钮（如「重新打开」「修改对账信息」）。

   - ① **时间范围选择**（先选时间）：默认**本月**；快捷项 本月 / 本季 / 全部 + 自定义起止日期；变更即重拉。
   - ② **总工单数行**（普通排版：左侧「总工单数」+ 右侧数值，非"大数字在前"）；附小字「时间范围 · 更新时间」（如 `本月 · 更新 16:37`）。
   - ③ **指标胶囊 Tab**：状态 / 大类 / 报修人排行——切换只展示当前一项；数据随 ① 的时间范围一并返回，切换 Tab 不重新请求。
   - ④ 当前 Tab 面板：
     - 状态：六种正式状态（待审核 / 待接单 / 处理中 / 已处理 / 已取消 / 已退回）行式：状态名（语义色）+ 计数 + 百分比 + 轻量占比条；`by_status` 恒返六态（count 可为 0）。
     - 大类：实际出现的大类 **Top5 + 其余合并「其他」**，行式 + 占比条（配色按序循环）；空态「暂无数据」。
     - 报修人排行：按报修单数从高到低取前 5（不足按实际）；真实头像（`avatar_url`，空回退首字）+ 昵称 + 单数，第 1 名高亮。
   - 空态：当前 Tab 无数据显示「暂无数据」；加载中显示「加载中…」。
3. **无下钻**：v1 各指标行点击不跳转列表。

**统计口径（与后端 5.17 约定一致）**
- 计入状态：`reported / pending_accept / processing / completed / cancelled / rejected` 六种正式状态；**草稿（draft）不计**。
- 时间归属：分布区按 `submitted_at`（最新一次正式提交时间，重提会刷新）落在所选范围内；今日概况卡按各自口径（存量/今日时间戳/动作时间），不受 `start`/`end` 影响。
- 报修人维度：工单**创建账号昵称**（`reporter`），非表单联系人（`contact`）。

```text
┌ 我的处理概况 ─────────────────── 收起 ▴ ┐
│ 可接单 12 │ 我的接单 8 │ 处理中 3 │ 已完工 5 │
│ ─────────────────────────────────────── │
│ 今日接单 2   今日完工 1   完工率 62%      │
```

- **位置**：页面最顶部（企业筛选 Header 与状态 Tab 之上），仅 `isStoreStaff()` 可见。

- **刷新时机**：进入页面（`onShow`→`init`）、切换企业、卡片动作成功后（`order-action-bar` 的 `done` → 同时刷新列表与统计）。
- **折叠**：点标题行右侧「收起/展开」切换；折叠态仅保留一行摘要（可接单 / 我的接单 / 已完工）。

- **数据源**：
  1. 已选大类 + 属性 → 取 `/orders/options` 树中该属性 `problems` 本地筛选（若后端后续提供按属性拉取的独立接口则切换，第十一章 #5）。
  2. 未选 / 未选全 → 「通用常见问题」接口（**后端待提供**，第十一章 #6；本期该区域可留空不展示）。
- **展示**：描述框（textarea）正下方，chips 横向换行排布；样式小号、次要（描边/浅底），不占视觉重心。
- **点击行为（关键）**：**以追加方式**写入 `description`——
  - 描述为空 → 直接写入该常见问题文本；
  - 描述非空 → 在末尾以空格（或换行）衔接追加，光标移至末尾；
  - **不整体替换**既有描述；已追加内容用户可在 textarea 中继续编辑 / 删除。
- 选择大类/属性变化时，chips 区自动刷新为该属性下的常见问题；已写入描述的文本不受影响。

### 7.4 保存与提交流程（沿用 V1.2 4.1 / 4.3）

- 提交成功 → 返回我的工单列表并刷新（订阅消息授权流程沿用 V1.2：提交时一次性请求三模板，拒绝不阻塞）。
