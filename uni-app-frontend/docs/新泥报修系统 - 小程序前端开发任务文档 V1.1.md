## 第一章 全局约定

### 1.1 底部 TabBar
小程序底部固定两个 Tab（**不随管理员模块变化**）：

| 位置 | 名称 | 页面路径 | 图标 |
|------|------|----------|------|
| 左侧 | 工单 | /pages/order/list | 工单图标 |
| 右侧 | 我的 | /pages/profile/index | 我的图标 |

### 1.2 管理员入口
管理员模块**不占用 TabBar**，入口位于「我的」页（`/pages/profile/index`）：

- 「我的」页 `onShow` 时解析本地 JWT，当 `payload.role === 1`（平台管理员）时，在用户信息卡片下方展示「管理」入口卡片。
- 点击「管理」入口 → `uni.navigateTo('/pages/admin/index')` → 管理员首页（企业管理 / 工单管理 双入口）。
- 非平台管理员不展示入口；直接访问管理页时，页面 `onShow` 守卫拦截并 Toast 提示后返回。

### 1.3 全局状态（Pinia）

| Store | 用途 | 关键字段 |
|-------|------|----------|
| userStore | 用户信息 | userInfo、token、isLoggedIn |
| enterpriseStore | 企业上下文 | currentEnterpriseId、enterprises |
| orderStore | 工单数据 | orderList、currentOrder |

> 管理员模块**不新增 Store**：管理列表数据为页面级状态，操作完成后重新拉取即可，避免全局状态膨胀。

### 1.4 请求封装
所有请求自动携带 `Authorization: Bearer <token>`，401 自动清除登录态并跳转登录页（`utils/request.ts` 已实现）。管理员接口（`/admin/*`、`/enterprises/*`）复用同一封装。

### 1.5 平台管理员角色判定（utils/jwt.ts 新增）

```typescript
// utils/jwt.ts（新增）
/**
 * 解析 JWT payload（base64url 解码第二段）。
 * 注意：微信小程序环境无原生 atob，需自行实现 base64url 解码
 * （或引入 base-64 等轻量库）。
 */
export function decodeToken(token: string): Record<string, unknown> | null {
  if (!token) return null
  try {
    const parts = token.split('.')
    if (parts.length < 2) return null
    const payload = parts[1]
      .replace(/-/g, '+')
      .replace(/_/g, '/')
    // 补齐 '=' 后 base64 解码并转 UTF-8，然后 JSON.parse
    return JSON.parse(base64UrlDecode(payload))
  } catch (e) {
    return null
  }
}

/**
 * 是否为平台管理员（role === 1）：
 * 优先读取登录/me 接口返回的 user.role（后端已确认返回该字段），
 * 兜底解析本地 JWT payload 的 role 字段。
 */
export function isPlatformAdmin(): boolean {
  const user = useUserStore().userInfo
  if (user && typeof user.role === 'number') {
    return user.role === 1
  }
  const token = uni.getStorageSync('token') as string
  return decodeToken(token)?.role === 1
}
```

> **角色值约定**：平台管理员 `role === 1`（经确认，与后端接口文档 3.1「role 的字段值必须为 1（平台管理员）」一致）。
>
> **判定方案（V1.1 实现确认）**：后端 `/auth/login` 与 `/auth/me` 的 user 对象已返回 `role` 字段（0/1），故 `isPlatformAdmin` 优先读取 `userInfo.role`，仅在本地尚未拉取到用户信息（如冷启动直达管理页）时，兜底解析 JWT payload。`decodeToken` / `base64UrlDecode` 保留供兜底使用。

### 1.6 登录流程（V1.1 更新）
```
App启动 → 检查是否有 token
    ├─ 有 token → 调用 /auth/me 验证
    │   ├─ 成功 → 进入首页
    │   └─ 失败 → 清除 token → 跳转登录页
    └─ 无 token → 跳转登录页
```
登录页：调用 `wx.login` 获取 code，调用 `POST /auth/login`。
- 老用户：返回 `access_token` + user，直接进入工单列表页
- 新用户：返回 `need_profile: true`，跳转资料完善页 `pages/auth/profile`

### 2.3 交互流程
1. 用户点击「微信一键登录」
2. 调用 `wx.login()` 获取 code

### 2.4 涉及的接口

| POST /auth/register | 新用户资料完善注册（昵称+头像+手机号） |
| POST /upload/avatar | 注册前头像上传（≤2MB，jpg/png/webp） |

### 2.5 资料完善页 /pages/auth/profile

| 项目 | 说明 |
|------|------|
| 功能 | 新用户首次登录后完善资料并完成注册 |
| 访问控制 | 新用户（need_profile=true）跳转进入 |

**布局与交互：**
1. 头像：`button open-type="chooseAvatar"` 选择头像 → 上传图床（`POST /upload/avatar`）
2. 昵称：`input type="nickname"` 输入微信昵称
3. 手机号：`button open-type="getPhoneNumber"` 微信授权获取 `phone_code`
4. 点击「完成注册」→ 重新 `wx.login()` 获取 code → `POST /auth/register` 传入 `{ code, nickname, avatar_url, phone_code }`
5. 成功：存储 token 与 user，跳转工单列表页

**邀请码二维码：**

| 项目 | 说明 |
|------|------|
| 入口 | 邀请码卡片「二维码」按钮 |
| 二维码内容 | `/enterprises/join?code={邀请码}`（`xxx` 为当前企业邀请码） |
| 展示方式 | 自绘遮罩浮窗：半透明黑遮罩 + 白底圆角卡片，卡片内展示二维码图片、企业名、邀请码，右上角「×」关闭按钮，点击遮罩也可关闭 |
| 技术方案 | 依赖 `weapp-qrcode`（基于微信小程序 canvas），`drawQrcode` 绘制到隐藏 canvas → `canvasToTempFilePath` 导出临时图片 → 赋值给浮窗内 `<image>` 展示 |

```typescript
// pages/admin/enterprise/detail.vue
import drawQrcode from 'weapp-qrcode'

data() {
  return {
    showQrcodePopup: false, // 浮窗显隐
    qrcodeImg: ''           // 生成的二维码临时图片
  }
}

/** 生成邀请码二维码并在浮窗中展示 */
showQrcode() {
  const code = this.ent?.invite_code
  if (!code) return
  this.qrcodeImg = ''
  this.showQrcodePopup = true // 先开浮窗展示"生成中"
  drawQrcode({
    width: 200,
    height: 200,
    canvasId: 'inviteQrcode',
    text: `/enterprises/join?code=${code}`,
    callback: () => {
      uni.canvasToTempFilePath({
        canvasId: 'inviteQrcode',
        success: (res) => {
          this.qrcodeImg = res.tempFilePath // 赋值后浮窗内 <image> 显示二维码
        }
      })
    }
  })
}
```

> **实现要点**：
> - 页面中放置一个移出屏幕的 `<canvas canvas-id="inviteQrcode">`（`position: fixed; left: 9999px`），**不可 `display:none`**，否则 `canvasToTempFilePath` 导出失败。
> - 浮窗为自绘 `view` 实现：`position: fixed` 全屏遮罩（半透明黑），点击遮罩关闭；内层卡片 `@click.stop` 阻止冒泡，右上角「×」按钮关闭。生成完成前浮窗内显示「生成中...」占位。
> - 用户扫码进入加入企业页时，`wx.scanCode` 解析二维码内容并自动提取 `code` 参数填充邀请码（复用 `/pages/enterprise/join` 的 `extractCode` 逻辑）。
> - `weapp-qrcode` 无内置类型声明，需在 `types/weapp-qrcode.d.ts` 中补充 `declare module` 类型。


**详情字段：** 用户端详情全部字段（`images`、`receipts`、`timeline`、`reject_reason`）+ `available_actions` 数组。

**available_actions 动作说明：**

| 当前状态 | 可选动作 | 说明 |
|----------|----------|------|
| reported | review、reject | 查阅、退回 |
| reviewed | accept、reject | 接单、退回 |
| processing | complete、reject | 完工、退回 |
| draft / completed / cancelled | 无 | 仅查看 |

**动作元素结构：**
```json
{
  "action": "reject",
  "label": "退回",
  "to_status": "draft",
  "require_reason": true,
  "reason_min_length": 10,
  "require_confirm": true,
  "confirm_message": "退回后报修人可修改重新提交，确认退回？"
}
```

**操作交互：**

| 操作 | 交互 | 接口 |
|------|------|------|
| 查阅 | 有 `require_confirm` 则先弹确认；`POST .../review`，body `{ remark }` | `/admin/orders/{id}/review` |
| 接单 | 同上，`POST .../accept`，body `{ remark }` | `/admin/orders/{id}/accept` |
| 退回 | 弹窗填原因（≥10 ≤200 字），`POST .../reject`，body `{ reason }` | `/admin/orders/{id}/reject` |
| 完工 | 弹窗填备注（≤200 字）+ 上传收据（≤3 张），`POST .../complete`，body `{ remark, receipts }` | `/admin/orders/{id}/complete` |

**退回弹窗：**
```
┌─────────────────────────┐
│  退回工单                │
│  退回原因：              │
│  [ textarea ]           │
│  10-200字符              │
│  [取消]    [确认退回]    │
└─────────────────────────┘
```

**完工弹窗：**
```
┌─────────────────────────┐
│  完工                    │
│  维修备注：              │
│  [ textarea ]（≤200字）  │
│  收据图片：              │
│  [ + 上传图片 ]          │
│  [img1][img2]（≤3张）    │
│  [取消]    [确认完工]    │
└─────────────────────────┘
```

**收据上传流程：**
1. `wx.chooseMessageFile`（count=1，过滤 jpg/png/webp，≤5MB）选择图片。
2. `POST /admin/orders/{id}/receipts`（multipart，字段名 `file`）上传，返回 `{ id, url, file_size }`。
3. 本地维护 `receiptUrls: string[]`（≤3 张），可删除。
4. 点击「确认完工」→ `POST /admin/orders/{id}/complete`，body `{ remark, receipts: receiptUrls }`（全量数组）。
5. 成功后刷新详情，展示完工状态与收据图片。

> **图片预览策略与用户端一致**：缩略图优先使用本地临时路径，`uni.previewImage` 放大预览使用远端 URL；真机环境需确保图床域名已加入 downloadFile 合法域名。

### 9.3 请求封装（utils/request.ts 新增）

```typescript
/**
 * 收据图片上传（POST /admin/orders/{order_id}/receipts，multipart/form-data）
 * 仅工单状态为 processing 时可上传，单张 ≤5MB，jpg/png/webp，同工单 ≤3 张
 */
export function uploadReceipt(
  orderId: string,
  filePath: string
): Promise<{ id: string; url: string; file_size: number }> {
  const token = uni.getStorageSync('token')
  return new Promise((resolve, reject) => {
    uni.uploadFile({
      url: `${BASE_URL}/admin/orders/${orderId}/receipts`,
      filePath,
      name: 'file',
      header: { Authorization: token ? `Bearer ${token}` : '' },
      success: (res) => {
        try {
          const body = JSON.parse(res.data) as ApiResponse
          if (body.code === 0) {
            resolve(body.data as never)
          } else {
            uni.showToast({ title: body.message || '上传失败', icon: 'none' })
            reject(body)
          }
        } catch (e) {
          reject(e)
        }
      },
      fail: (err) => {
        uni.showToast({ title: '上传失败，请重试', icon: 'none' })
        reject(err)
      }
    })
  })
}
```
