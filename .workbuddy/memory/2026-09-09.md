## 编辑页返回拦截：脏检查 + 微信左上角"<"拦截
- 关键发现：微信小程序 `onBackPress` 只能监听、无法阻止返回（H5/App 才行）。微信端拦截左上角"<"必须用 `<page-container>` 的 `@beforeleave`。
- 脏检查：`init()` 末尾 `captureSnapshot()` 拍下 `form`+图片URL快照；`isDirty()` 对比当前状态。未改动时返回直接退出、不弹窗。
- 微信端：`#ifdef MP-WEIXIN` 用 `<page-container :show="containerShow" :overlay="false" @beforeleave="onContainerLeave">` 包裹整页；`onContainerLeave` 先把 `containerShow=false` 消耗一次返回事件，再 `promptExit()`（未加载完/已在退出则直接 `doExit`）。
- 非微信端：`onBackPress` 中 `#ifdef MP-WEIXIN return false` 放行，其余平台 `return true` 拦截。
- `promptExit()`：未 dirty→直接退出；有改动→弹窗"是否保存该工单草稿？"(保存/不保存)；点遮罩→停留并 `containerShow=true` 恢复拦截。
- 防自拦截：提交/参数错误自动 `navigateBack` 前设 `exiting=true`，`onContainerLeave` 见 exiting 直接放行，避免保存/提交后又弹窗。
- 校验：`@vue/compiler-sfc` 编译通过，关键符号(onContainerLeave/promptExit/isDirty/captureSnapshot/onBackPress)齐全。

## 编辑页返回拦截 Bug 修复（空白页 + 空草稿不弹窗）
- 空白页根因：之前把**整页内容都包进 `<page-container>`**。微信 page-container 会把子内容渲染到独立覆盖层，`beforeleave` 内 `containerShow=false` 消耗返回事件时该层隐藏，主页面内容为空 → 返回过程中闪空白页。
- 修复：`page-container` 改为**空兄弟节点**（仅 `:show`/`:overlay=false`/`@beforeleave`），不再包裹内容；真实内容留在主页面，`show` 切换不再影响可见内容。
- 空草稿不弹窗（真因）：`init()` 原先先做「仅一个可选单位时自动选中企业」**再**拍快照，导致单企业账号下草稿一加载 `enterprise_id` 就被自动填值 → 快照非空 → `isSnapshotEmpty()`/`isDirty()` 均 false → 直接退出、不弹窗。
- 修复：将 `captureSnapshot()`+`loaded=true` 提前到自动选企业**之前**；自动选择算作用户改动，基础加载态（企业未选）才作为脏检查基准。现单/多企业账号下新建空草稿点返回均会弹窗。
- 校验：`@vue/compiler-sfc` 编译通过；page-container 不再包裹内容，且快照时序已修正。

## 编辑页返回行为变更：空草稿自动删除（不再弹窗）
- 用户最终决定：进来完全不改（空草稿）返回时**直接自动删除**，不弹窗。
- 改 `promptExit()` 逻辑（移除 `shouldPrompt()`）：
  1. `isSnapshotEmpty()` 为真（加载时即空白草稿）→ `await deleteDraft(true)` 直接删+退出，不弹窗；
  2. 否则 `!isDirty()`（已填内容但本次未改）→ `doExit()` 保留草稿直接退出；
  3. 否则（有改动）→ 弹窗"是否保存该工单草稿？"（保存/不保存）。
- 边界：已填好的旧草稿若未改动，仅直接保留退出（不删、不弹窗），避免误删用户数据；只有"空白草稿且未改"才自动删。
- 校验：`@vue/compiler-sfc` 解析+编译 edit.vue OK；`shouldPrompt` 已无残留引用。

### 二次修正：单企业账号新建空草稿仍弹窗（根因）
- 根因①：原 `init()` 中「自动选中企业」发生在 `captureSnapshot()` **之后**，导致快照里 `enterprise_id` 为空、而实际被自动填充 → `isDirty()` 误判为"有改动"。
- 根因②：`isSnapshotEmpty()` 把 `urgency` 纳入空判，后端对 `urgency` 有默认值（如 'normal'）→ 误判"非空草稿"。两者叠加，空草稿落入了"有改动→弹窗"分支。
- 修复：
  1. `init()` 把 `captureSnapshot()` 移到「自动选中企业」**之后**拍，使自动选择不计入用户改动；
  2. 删除 `isSnapshotEmpty()`，新增 `isFormBlank()`——仅看用户手填核心内容（description/room/contact_name/contact_phone/图片），忽略企业、紧急程度等默认值或自动选择；`init()` 末尾据其计算 `wasEmptyOnLoad`；
  3. `promptExit()` 改用 `!isDirty() && wasEmptyOnLoad` 判定自动删除，`!isDirty()` 单独判定"未改保留退出"。
- 校验：`@vue/compiler-sfc` 解析+编译 edit.vue OK；`isSnapshotEmpty`/`shouldPrompt` 已无残留引用。

### 三次修正：半填草稿（未改）返回被误删
- 现象：进入“填了一半”的草稿编辑页、不动直接返回 → 被直接删除。
- 根因：`isFormBlank()` 只看 description/room/contact_name/contact_phone/images 四个“核心”字段。用户若只填了企业/分类/属性/紧急程度（description 还没填），这些字段仍空 → `wasEmptyOnLoad=true`，叠加 `isDirty()=false` → 落到自动删分支。
- 修复：废弃前端 form 视角的 `isFormBlank()`，改为基于**后端原始 `detail`** 全部可填字段的 `isBlankDraft(d)`（enterprise_id/category_id/property_id/description/urgency/room/contact/images 全空才为空白）；且 `wasEmptyOnLoad` 计算移到 `applyDetail` 之后、自动选企业**之前**，彻底隔离前端自动选择干扰。
- 结果：仅“后端存储的全空草稿且未改”才自动删；任意字段填过（含分类/紧急程度等）的草稿未改返回均保留；有改动仍弹窗。
- 校验：`@vue/compiler-sfc` 解析+编译 edit.vue OK；`isFormBlank` 已无残留引用。
