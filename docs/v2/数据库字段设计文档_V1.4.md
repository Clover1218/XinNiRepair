## 第一章 概述

### 1.1 设计原则

| 原则 | 说明 |
|------|------|
| **后端生成主键** | 所有 `id` 字段在后端用 `uuid.Must(uuid.NewV7()).String()` 生成，不依赖数据库默认值，便于业务层提前获取 ID |
| **GORM 优先** | 字段类型与 GORM 标签对齐，避免使用 GORM 不友好的数据库特性（如原生 ENUM） |
| **索引覆盖查询** | 所有查询场景均有对应索引，后台筛选、排序不扫全表 |
| **审计可追溯** | `order_timeline` 记录工单全生命周期操作，`audit_logs` 记录管理员关键操作 |
| **字典软删除** | 项目大类/属性/常见问题为**字典表**，删除采用软删除（`deleted_at`），ID 永久保留；工单引用的字典名以**快照列**留存，避免字典改名/删除影响历史单展示 |
| **无"退回态"** | 退回不是独立状态：退回操作将工单状态置回 `draft` 并保留 `reject_reason`，前端「已退回」筛选由时间轴最近一次 `reject` 动作派生 |
| **范围外保留** | 对账/完工费用、room/contact 等字段为既有实现且生产在用，本版按《需求说明书 V1.2》（2026-09-06 就地修订，财务对账纳入范围）继续收录 |

### 1.2 数据库选型

| 项目 | 说明 |
|------|------|
| 数据库 | PostgreSQL 15+ |
| 字符集 | UTF-8 |
| 时区 | TIMESTAMPTZ（UTC 存储，应用层转 Asia/Shanghai） |
| 主键策略 | UUID v7（后端生成，`github.com/google/uuid`） |
| ORM 框架 | GORM v2（`gorm.io/gorm` + `gorm.io/driver/postgres`） |
| 软删除 | 字典表用 `deleted_at`（软删，ID 保留）；业务表（企业/用户/工单）**不使用** `gorm.DeletedAt`，删除/移除记录到 `audit_logs`，数据永久保留 |

### 1.3 命名规范

| 对象类型 | 规范 | 示例 |
|----------|------|------|
| 表名 | 小写 + 下划线，复数 | `repair_orders` |
| 字段名 | 小写 + 下划线 | `enterprise_id` |
| 主键 | `id`（UUID） | `id UUID PRIMARY KEY` |
| 状态字段 | `status`（VARCHAR + Go 常量） | `status VARCHAR(20) NOT NULL DEFAULT 'draft'` |
| 索引 | `idx_表名_字段` | `idx_orders_status` |
| 时间戳 | `created_at`, `updated_at` | TIMESTAMPTZ，GORM 自动管理 |
| 软删除 | `deleted_at TIMESTAMPTZ NULL` | NULL=有效，非 NULL=已软删除 |
| 排序 | `sort_order SMALLINT NOT NULL DEFAULT 0` | 字典展示顺序，升序 |

### 1.4 Go 常量定义（替代数据库枚举）

所有状态字段在 Go 代码中用常量管理，数据库层只存字符串值。

```go
const (
    OrderStatusDraft        = "draft"          // 草稿
    OrderStatusReported     = "reported"       // 已上报（等待本单位单位审核员审核）
    OrderStatusPendingAccept = "pending_accept" // 待接单（单位审核员已审核通过，等待维修业务员接单）
    OrderStatusProcessing   = "processing"     // 处理中
    OrderStatusCompleted    = "completed"      // 已处理/完成（终态）
    OrderStatusCancelled    = "cancelled"      // 已取消（终态）
)

// ActionType 操作类型
const (
    ActionCreateDraft   ActionType = "create_draft"
    ActionSubmit        ActionType = "submit"
    ActionAudit         ActionType = "audit"           // 审核通过：reported → pending_accept（单位审核员）
    ActionAccept        ActionType = "accept"          // 接单维修：pending_accept → processing（维修业务员）
    ActionComplete      ActionType = "complete"        // 完工：processing → completed
    ActionReopen        ActionType = "reopen"          // 重新打开：completed → processing
    ActionReject        ActionType = "reject"          // 退回：reported/pending_accept/processing → draft
    ActionCancel        ActionType = "cancel"          // 取消：draft/reported/pending_accept → cancelled
    ActionUploadReceipt ActionType = "upload_receipt"
    ActionUpdateFinance ActionType = "update_finance"  // 修改对账信息
)
```

> 说明：旧版本 `review`（查阅，reported→reviewed）与 `reviewed` 状态在 V1.4 移除。历史时间轴中的 `review` 动作保留原值，前端可映射展示为「审核通过」；历史 `reviewed` 状态数据回填为 `pending_accept`。

## 第二章 核心表字段详解

### 2.1 enterprises — 企业（单位）表

| 序号 | 字段名 | 类型 | 约束 | 默认值 | 说明 |
|------|--------|------|------|--------|------|
| 1 | id | UUID | PRIMARY KEY | — | 企业唯一标识，后端生成 UUID v7 |
| 2 | name | VARCHAR(50) | NOT NULL | — | 企业（单位）名称，2-50 字 |
| 3 | invite_code | VARCHAR(8) | NOT NULL, UNIQUE | — | 邀请码，6 位字母数字组合，系统自动生成，可刷新有效期 |
| 4 | auto_approve | BOOLEAN | NOT NULL | FALSE | 是否免审核加入（扫码直接成为成员） |
| 5 | status | SMALLINT | NOT NULL | 1 | 1=正常 / 0=已注销 |
| 6 | invite_code_expires_at | TIMESTAMPTZ | — | NULL | 邀请码过期时间（NULL=永久有效） |
| 7 | created_at | TIMESTAMPTZ | NOT NULL | NOW() | 创建时间（GORM autoCreateTime） |
| 8 | updated_at | TIMESTAMPTZ | NOT NULL | NOW() | 更新时间（GORM autoUpdateTime） |

**GORM 模型：**

```go
type Enterprise struct {
	ID                  string       `gorm:"primaryKey;type:uuid"`
	Name                string       `gorm:"type:varchar(50);not null;uniqueIndex"`
	InviteCode          string       `gorm:"type:varchar(8);not null;uniqueIndex"`
	AutoApprove         bool         `gorm:"not null;default:false"`
	Status              int          `gorm:"not null;default:1;index"`
	InviteCodeExpiresAt *time.Time   `gorm:"type:timestamptz"`
	CreatedAt           time.Time    `gorm:"autoCreateTime"`
	UpdatedAt           time.Time    `gorm:"autoUpdateTime"`
	Memberships         []Membership `gorm:"foreignKey:EnterpriseID"`
}
```

**索引：** `enterprises_pkey(id)`；`idx_enterprises_invite_code(invite_code)` UNIQUE；`idx_enterprises_status(status)` BTREE。

### 2.2 users — 用户表

| 序号 | 字段名 | 类型 | 约束 | 默认值 | 说明 |
|------|--------|------|------|--------|------|
| 1 | id | UUID | PRIMARY KEY | — | 用户唯一标识，后端生成 UUID v7 |
| 2 | openid | VARCHAR(64) | NOT NULL, UNIQUE | — | 微信 OpenID |
| 3 | unionid | VARCHAR(64) | — | NULL | 微信开放平台 UnionID（可选） |
| 4 | nickname | VARCHAR(32) | NOT NULL | — | 昵称（微信昵称或后台昵称） |
| 5 | password | VARCHAR(100) | — | NULL | 登录密码，bcrypt 哈希；平台侧账号必填，微信用户可为空 |
| 6 | avatar_url | VARCHAR(512) | — | NULL | 微信头像 URL |
| 7 | phone | VARCHAR(20) | 部分唯一索引 | NULL | 手机号（非空时唯一） |
| 8 | role | INT2 | NOT NULL | 0 | **0=普通用户(报修人) / 1=维修业务员(原平台管理员) / 2=超级管理员** |
| 9 | created_at | TIMESTAMPTZ | NOT NULL | NOW() | 注册时间 |
| 10 | updated_at | TIMESTAMPTZ | NOT NULL | NOW() | 更新时间 |

> role=1（维修业务员）即原「平台管理员」，店方维修人员，可在 Web 管理后台与小程序处理工单（接单/处理/完工/上传收据/退回），并查看个人已接业务与汇总。「业务员仅限本单位接单」为业务规则约束（见接口设计），表结构层面通过工单 `repairer_id` 归属实现可追溯，不新增单位关联表。

**GORM 模型：**

```go
type User struct {
    ID        string     `gorm:"primaryKey;type:uuid"`
    Openid    string     `gorm:"type:varchar(64);not null;uniqueIndex"`
    Unionid   string     `gorm:"type:varchar(64);index"`
    Nickname  string     `gorm:"type:varchar(32);not null"`
    Password  string     `gorm:"type:varchar(100)"`
    AvatarUrl string     `gorm:"type:varchar(512)"`
    Phone     string     `gorm:"type:varchar(20);index"`
    Role      int        `gorm:"type:smallint;not null;default:0;index"`
    CreatedAt time.Time  `gorm:"autoCreateTime"`
    UpdatedAt time.Time  `gorm:"autoUpdateTime"`

    Memberships    []Membership  `gorm:"foreignKey:UserID"`
    RepairOrders   []RepairOrder `gorm:"foreignKey:ReporterID"`
}
```

**索引：** `users_pkey(id)`；`idx_users_openid(openid)` UNIQUE；`idx_users_unionid(unionid)` BTREE；`idx_users_phone(phone)` 部分唯一（`WHERE phone IS NOT NULL AND phone <> ''`）；`idx_users_role(role)` BTREE。

### 2.3 memberships — 企业（单位）成员关系表

| 序号 | 字段名 | 类型 | 约束 | 默认值 | 说明 |
|------|--------|------|------|--------|------|
| 1 | id | UUID | PRIMARY KEY | — | 关系唯一标识 |
| 2 | enterprise_id | UUID | FK → enterprises(id), NOT NULL | — | 所属单位 |
| 3 | user_id | UUID | FK → users(id), NOT NULL | — | 用户 |
| 4 | role | INT2 | NOT NULL | 0 | **0=普通成员 / 1=单位审核员**（原"企业管理员"，可多人） |
| 5 | status | VARCHAR(20) | NOT NULL | 'pending' | pending / approved / rejected / removed |
| 6 | joined_at | TIMESTAMPTZ | — | NULL | 审核通过（成为正式成员）时间 |
| 7 | removed_at | TIMESTAMPTZ | — | NULL | 移除时间 |
| 8 | created_at | TIMESTAMPTZ | NOT NULL | NOW() | 申请时间 |

**唯一约束：** `UNIQUE(enterprise_id, user_id)` — 同一用户在同一单位仅一条记录。

> 角色职责映射：role=1「单位审核员」在原"企业管理员"（成员审批、企业设置）职责基础上，按说明书 3.5 增加：审核本单位 `reported` 工单（通过→`pending_accept` / 退回→`draft`）、查看本单位全部工单、工单汇总统计。单位审核员可有多人；报修人可以是普通成员，也可以是单位审核员自己（说明书允许审核员同时上报）。工单是否由"单位审核员审核通过"通过 `repair_orders.audited_by` 记录。

**GORM 模型：**

```go
type Membership struct {
    ID           string     `gorm:"primaryKey;type:uuid"`
    EnterpriseID string     `gorm:"type:uuid;not null;index:idx_memberships_enterprise"`
    UserID       string     `gorm:"type:uuid;not null;index:idx_memberships_user"`
    Role         int        `gorm:"type:smallint;not null;default:0;index"` // 0=普通成员 1=单位审核员
    Status       string     `gorm:"type:varchar(20);not null;default:'pending'"`
    JoinedAt     *time.Time `gorm:"type:timestamptz"`
    RemovedAt    *time.Time `gorm:"type:timestamptz"`
    CreatedAt    time.Time  `gorm:"autoCreateTime"`

    Enterprise Enterprise `gorm:"foreignKey:EnterpriseID"`
    User       User       `gorm:"foreignKey:UserID"`
}
```

**索引：** `memberships_pkey(id)`；`idx_memberships_enterprise(enterprise_id)`；`idx_memberships_user(user_id)`；`idx_memberships_status(enterprise_id,status)`；`idx_memberships_role(enterprise_id,role)`；`memberships_enterprise_user_key(enterprise_id,user_id)` UNIQUE。

### 2.4 project_categories — 项目大类表（新，替代 JSON 存储）

> 说明书 3.7 的"项目大类管理"（超级管理员专属 CRUD）由 `/data/project_categories.json` 文件迁移到数据库，原 JSON 作为种子数据导入。需求方确认：大类/属性/常见问题均**单独建表**、软删除（ID 保留）、支持排序。

| 序号 | 字段名 | 类型 | 约束 | 默认值 | 说明 |
|------|--------|------|------|--------|------|
| 1 | id | UUID | PRIMARY KEY | — | 大类 ID（原 JSON 中 id 为字符串键，如 `desktop_repair`，入库后使用 UUID v7） |
| 2 | name | VARCHAR(50) | NOT NULL | — | 大类名称（如"电脑维修"） |
| 3 | description | VARCHAR(200) | NOT NULL | '' | 大类描述 |
| 4 | sort_order | SMALLINT | NOT NULL | 0 | 展示顺序，升序 |
| 5 | deleted_at | TIMESTAMPTZ | — | NULL | 软删除时间；NULL=有效。删除仅置此列，**ID 与行保留**（历史工单仍可通过 category_id 关联统计） |
| 6 | created_at | TIMESTAMPTZ | NOT NULL | NOW() | 创建时间 |
| 7 | updated_at | TIMESTAMPTZ | NOT NULL | NOW() | 更新时间 |

**唯一约束：** `name` 在未删除记录中唯一（部分唯一索引 `WHERE deleted_at IS NULL`）。

**GORM 模型：**

```go
type ProjectCategory struct {
    ID          string     `gorm:"primaryKey;type:uuid"`
    Name        string     `gorm:"type:varchar(50);not null"`
    Description string     `gorm:"type:varchar(200);not null;default:''"`
    SortOrder   int        `gorm:"type:smallint;not null;default:0"`
    DeletedAt   *time.Time `gorm:"type:timestamptz;index"`
    CreatedAt   time.Time  `gorm:"autoCreateTime"`
    UpdatedAt   time.Time  `gorm:"autoUpdateTime"`

    Properties []ProjectProperty `gorm:"foreignKey:CategoryID"`
}
```

**索引：** `project_categories_pkey(id)`；`uq_project_categories_name(name) WHERE deleted_at IS NULL` UNIQUE(部分)；`idx_project_categories_active(sort_order) WHERE deleted_at IS NULL`(部分)。

### 2.5 project_properties — 项目属性表（新）

> 每个项目大类拥有自己的"项目属性"（category ↔ property 一对多）。报修单必须选择所在大类的某个属性并落库（`repair_orders.property_id`）。示例：大类"电脑维修"→ 属性可配置为 台式机/笔记本/一体机 等（由超管维护）。

| 序号 | 字段名 | 类型 | 约束 | 默认值 | 说明 |
|------|--------|------|------|--------|------|
| 1 | id | UUID | PRIMARY KEY | — | 属性 ID |

**状态流转图：**

```
draft ──提交──→ reported ──审核通过(单位审核员)──→ pending_accept ──接单(维修业务员)──→ processing ──完工──→ completed
  草稿          已上报              |                   待接单            |             处理中            已处理/完成
                                   |                    |                  |
   ↑  │                          │退回                │退回              │退回        (completed 可重新打开 → processing)
   │  │                          └────────────────────┴──────────────────┘
   │  │取消(draft/reported/pending_accept，报修人)→ cancelled（终态，列表底部单独展示）
   │  └── 退回/取消均需填写原因（退回原因 ≥10 字）
```

**退回/取消派生规则：**
- "退回"不是状态：`status` 置回 `draft`，同时**清空** `submitted_at/audited_at/audited_by/accepted_at/repairer_id`（如适用），保留 `reject_reason` 与时间轴 `reject` 记录。
- 前端「已退回」筛选项 = 最近时间轴含 `reject` 且当前为 `draft` 的工单（由服务层派生，不做状态枚举）。
- "取消"为终态 `cancelled`（写时间轴 `cancel`），列表/首页底部单独分组展示；终态（completed/cancelled）不可再流转。

## 附录 A — 工单号生成规则

**格式：** `XNB-{YYYYMMDD}-{3位序号}`（如 `XNB-20260827-001`，每日从 001 重新开始计数）

**生成时机：** 提交上报时生成（草稿无单号，`order_no=NULL`）。

**生成逻辑（后端实现）：**

```go
func GenerateOrderNo(db *gorm.DB) (string, error) {
    today := time.Now().Format("20060102")
    prefix := "XNB-" + today + "-"

    var lastNo string
    db.Model(&RepairOrder{}).
        Where("order_no LIKE ?", prefix+"%").
        Order("order_no DESC").
        Limit(1).
        Pluck("order_no", &lastNo)

    seq := 1
    if lastNo != "" {
        seqStr := lastNo[len(prefix):]
        if s, err := strconv.Atoi(seqStr); err == nil {
            seq = s + 1
        }
    }
    return prefix + fmt.Sprintf("%03d", seq), nil
}
```
