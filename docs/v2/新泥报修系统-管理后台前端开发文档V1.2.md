## V1.2 更新说明（对照后端接口文档 V1.2）

1. **角色体系（双层模型）重写**：`users.role` 0=普通用户 / 1=维修业务员 / 2=超级管理员；单位内成员身份 `memberships.role` 0=普通成员 / 1=单位审核员，接口字符串统一为 `member` / `reviewer`。
2. **Web 后台登录开放“单位审核员”**：有密码的单位审核员（role=0 + membership.role=1）可登录 Web；无密码账号需由超级管理员先经“用户管理 → 重置密码”（V1.2 后端 6.4 已放行审核员）开通登录密码。
3. **登录后按“平台角色 × 成员身份”裁剪菜单与页面**（见第二章），审核员仅可看其担任审核员的单位数据。
4. **企业管理模块**：成员列表展示单位内身份（单位审核员/普通成员）；维修业务员/超级管理员新增【设为单位审核员】【取消审核员】操作（新增接口 `PUT /enterprises/{id}/members/{uid}/role`，见 5.2.2）；单位审核员登录后仍可审批成员（通过/拒绝/移除/刷新邀请码/单位设置），**但不提供**提升/降级他人为审核员按钮。
5. **工单状态机对齐 V1.4**：draft → reported(已上报/待审核) → pending_accept(待接单) → processing(处理中) → completed(已处理)；动作枚举 `audit`(审核通过)/`accept`/`complete`/`reject`/`reopen`/`update_finance`；工单字段为大类/属性两级（`category_id/category_name/property_id/property_name` 快照）。
6. **新增“单位审核”视图**：登录用户若在某一企业担任单位审核员，进入该视图选择单位后，可对本单位 `reported`（已上报）工单执行【审核通过（上报维修业务员）】/【退回】，并查看本单位全部工单（仅限本单位，跨单位不可见）。
7. **超级管理员新增“项目字典”模块**：项目大类 / 项目属性 / 常见问题三类数据增删改查（软删除 + 排序），对应后端 6.5 `/admin/categories` `/admin/properties` `/admin/problems`。
8. 工单详情/列表字段、状态 Tab、操作区按 available_actions 驱动渲染（见第六章）；`review` 动作已移除（后端保留 `/review` 兼容别名，V1.2 前端不再调用）。
> **[2026-09-07 就地修订补充]** 前端交互三项优化：
> 1. **项目字典页升级为“大类 | 属性 | 常见问题”三栏联动**：项目属性与大类一样可点选，选中某属性后第三栏联动展示该属性下常见问题（不再用独立下拉/孤立面板维护问题）。
> 2. **大类/属性/常见问题顺序均支持前端拖拽排序**（引入 `sortablejs`，按住行尾拖拽手柄拖动；拖动结束即按新顺序逐个调用 `updateCategory/updateProperty/updateProblem` 写回 `sort_order=1..n`）；新增/编辑弹窗不再提供“排序”手工输入，新建默认排到末尾。
> 3. **单位审核员登录后侧边栏独立展示【单位审核】与【企业管理】两项菜单**：企业相关操作（成员审批/单位设置/邀请码等）收敛到“企业管理”，审核页不再承载企业管理职责；多审核单位时企业详情页顶栏可切换单位。

```typescript
// stores/user.ts（更新：基于双层的计算属性）
export const useUserStore = defineStore('user', {
  state: () => ({ token: '', userInfo: null as UserInfo | null }),
  getters: {
    // 平台店方角色（维修业务员/超管，可跨单位操作）
    isStoreStaff: (s) => !!s.userInfo && s.userInfo.role >= 1,
    isSuperAdmin: (s) => s.userInfo?.role === 2,
    // 本人担任“单位审核员”的单位（approved 且 role=reviewer）
    reviewerEnterprises: (s) =>
      (s.userInfo?.enterprises ?? []).filter(e => e.status === 'approved' && e.role === 'reviewer'),
    // 是否具备审核入口（登录后可进“单位审核”视图）
    hasReviewerRole: (s) => s.reviewerEnterprises.length > 0,
    // 判断某单位是否可管理（审核员限本单位）
    canManageEnterprise: (s) => (entId: string) =>
      s.isStoreStaff || s.reviewerEnterprises.some(e => e.enterprise_id === entId),
  },
  actions: { /* setUser/logout 同 V1.1 */ }
})
```

> 说明：登录响应 `user.enterprises[].role` 由后端按 `reviewer`/`member` 返回（V1.2 接口文档 2.4/3.5）。

### 2.3 菜单矩阵

| 菜单/页面 | 维修业务员(role=1) | 超级管理员(role=2) | 单位审核员(role=0, reviewer) | 普通成员 |
| --- | --- | --- | --- | --- |
| 工单管理 `/orders` | ✅ 全部单位（可按单位筛选） | ✅ | ✅ 仅其担任审核员的单位（enterprise_id 必带） | —（小程序端） |
| 企业管理 `/enterprises`（店方）/ 企业详情 `/enterprises/:id`（审核员） | ✅ 全部单位 | ✅ | ✅ 侧栏独立菜单，直达其担任审核员的首个单位详情，可在页内切换其他审核单位 | — |
| 单位审核 `/review` | 不显示（见工单管理） | 不显示 | ✅ 单位切换 + 待审核/退回 | — |
| 项目字典 `/dictionary` | — | ✅ | — | — |
| 用户管理 `/users` | — | ✅（含为审核员设置密码） | — | — |

> 说明：role=1 用户若同时在某单位担任“单位审核员”，其工单管理页面拥有店方全部操作（含审核），且天然可进该单位企业详情；菜单不做重复入口。

> 审核员侧边栏固定展示两个菜单：【单位审核】`/review`（本单位工单审核/退回）与【企业管理】（进入担任审核员的首个单位详情；多个审核单位时，详情页顶栏提供单位切换下拉）。两者职责分离，单位审核页不再内嵌企业成员管理等操作。
> 审核员工单数据域限制（v1.2 后端 5.1）：接口调用必须带 `enterprise_id`，仅限审核员本单位；`/admin/orders`、详情、audit、reject（reported）均已由后端按 Operator 校验。

### 2.4 路由守卫与登录跳转

```typescript
// router/index.ts 守卫（示意）
router.beforeEach((to, _from, next) => {
  const userStore = useUserStore()
  if (to.meta.requiresAuth && !userStore.token) { next('/login'); return }

  const perms = (to.meta.permissions ?? []) as string[]
  const ok = perms.some(p =>
    (p === 'store' && userStore.isStoreStaff) ||
    (p === 'super' && userStore.isSuperAdmin) ||
    (p === 'reviewer' && userStore.hasReviewerRole)
  )
  if (to.meta.requiresAuth && !ok) {
    // 无权限：店方 → /orders；仅审核员 → /review；其它登出
    next(userStore.hasReviewerRole ? '/review' : userStore.isStoreStaff ? '/orders' : '/login')
    return
  }
  next()
})
```

## 第八章 项目字典模块（超管，V1.2 新增）

**入口**：侧边栏【项目字典】`/dictionary`（仅 `role===2`）。对应后端 6.5；数据为**三级树形：大类 → 属性 → 常见问题**（常见问题直接隶属项目属性），删除为软删除（ID 保留，历史工单展示不受影响）。删除大类级联软删其下属性及问题；删除属性级联软删其下问题。

### 8.1 页面结构（三栏联动）

项目字典为**三栏联动布局**：大类 → 属性 → 常见问题，三列均可点选、可拖拽排序；数据由一次 `getCategories()`（三级树形）返回，前端本地维护选中态。

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 项目字典                                                             │
│ ┌────────────────┬──────────────────┬───────────────────────────────┐ │
│ │ 项目大类        │ 项目属性(选中大类)│ 常见问题(选中属性)          │ │
│ │ [＋新增大类]    │ [＋新增属性]      │ [＋新增问题]                │ │
│ │ ┌───────────┐  │ ┌─────────────┐  │ 当前属性：维修               │ │
│ │ │▣ 电脑     │  │ │▣ 维修(5问题) │  │ ┌─────────────────────────┐ │ │
│ │ │ 办公外设   │  │ │  保修(2问题) │  │ │ 主板损坏  [编辑][删除]  │ │ │
│ │ │ 网络设备   │  │ │  更换(3问题) │  │ │ 无法开机  [编辑][删除]  │ │ │
│ │ └───────────┘  │ └─────────────┘  │ └─────────────────────────┘ │ │
│ └───────────────┴────────────────┴───────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────────┘
```

- 第 1 栏（项目大类）：点击整行即选中，右侧两栏联动到该大类数据。
- 第 2 栏（项目属性）：**与大类一样可点选**；选中某属性后第 3 栏联动展示该属性下常见问题（不再用独立下拉/孤立面板）。未选大类时属性栏为空态、新增按钮不可用。
- 第 3 栏（常见问题）：面板标题下显示“当前属性：xxx”；无选中属性时为空态引导，新增问题按钮不可用。
- 属性/问题列表行内展示数量（属性行：N 问题；大类行：N 属性），便于定位。

### 8.2 选中规则

- 进入页面默认选中第一个大类，并自动选中其第一个属性联动展示问题。
- 切换大类：自动选中该大类第一个属性（若有）并刷新问题栏；切换属性：问题栏即时切换。
- 删除当前选中的大类/属性/问题后，选中态自动回退到剩余第一项或显示空态。

### 8.3 拖拽排序（替代手工序号输入）

- 三个列表每行行尾都有拖拽手柄图标（Rank 图标）；按住手柄上下拖动即调整顺序（引入 `sortablejs`；除手柄外的整行点击仍为选中）。
- **拖动结束即自动保存**：将列表按新顺序重写为 `sort_order = 1..n`，仅对有变化的行发出请求：

| 层级 | 请求 |
| --- | --- |
| 大类 | `updateCategory(id, { sort_order })` |
| 属性 | `updateProperty(id, { sort_order })` |
| 问题 | `updateProblem(id, { sort_order })` |

- 保存中整页 loading；成功提示“顺序已保存”；失败自动 `getCategories()` 回滚为服务端顺序并提示错误。
- 新增记录自动排到末尾（新建请求自动携带当前最大值 +1 的 `sort_order`，后端按 `sort_order` 升序返回）。
- 新增/编辑弹窗**不再提供“排序”手工输入框**。

### 8.4 新增/编辑字段（不含排序）

| 类型 | 名称（必填） | 描述（≤200） | 常见解决建议 | 提交归属 |
| --- | --- | --- | --- | --- |
| 大类 | ≤50，全库唯一 | 选填 | — | — |
| 属性 | ≤50，同大类内唯一 | 选填 | — | `category_id`（当前选中大类，弹窗内只读展示） |
| 常见问题 | ≤100，同属性内唯一 | 选填 | 多标签编辑（回车添加/删除） | `property_id`（当前选中属性；编辑弹窗内可切换目标属性） |

- 删除均为软删除且需二次确认：删大类级联隐藏其属性与问题；删属性级联隐藏其问题；历史工单展示不受影响（ID 保留、名称快照）。

### 8.5 空态与刷新

- 无大类：第 1 栏空态 + “新增大类”；无属性：第 2 栏“暂无属性，请新增”；无问题：第 3 栏“该属性下暂无常见问题”。

- 所有增删改成功均提示并整体 `getCategories()` 刷新；字典变更即时生效（无需重启）。
