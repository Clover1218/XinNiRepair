## 第一章 全局约定（V1.2 重写）

### 1.1 角色与身份判定（双层模型）

沿用《后端接口设计文档 V1.2》1.1 的双层模型：

| 维度 | 取值 | 说明 |
|------|------|------|
| 全局角色 `users.role` | `0` 普通用户 / `1` 维修业务员（店方）/ `2` 超级管理员 | 决定端与基础权限，JWT payload 与 `/auth/me` 的 `user.role` 均返回 |
| 单位内成员身份 `memberships.role` | `0` 普通成员 / `1` 单位审核员 | 接口字符串 `member` / `reviewer`（兼容旧值 `admin`），`/auth/me` 返回 `enterprises[].role` |

> ⚠️ 与 V1.1 差异：V1.1 的“平台管理员（role===1 唯一管理员入口）”已废弃；role=1 语义统一为**维修业务员（店方）**，且 role=2 超级管理员存在。单位审核员是 **role=0 的微信普通用户**在某个单位内担任 `reviewer` 身份，可多人、可同时担任多个单位的审核员。

**能力判定（utils/auth.ts，替代原 `utils/jwt.ts` 的 `isPlatformAdmin`）**

```typescript
// utils/auth.ts（V1.2 新增，替代 utils/jwt.ts 的 isPlatformAdmin 语义）
import { decodeToken } from '@/utils/jwt'   // base64url 解码逻辑保留
import { useUserStore } from '@/stores/user'

type PlatformRole = 0 | 1 | 2
type MemberRole = 'member' | 'reviewer'

function platformRole(): PlatformRole {
  const user = useUserStore().userInfo
  if (user && typeof user.role === 'number') return user.role as PlatformRole
  const token = uni.getStorageSync('token') as string
  return (decodeToken(token)?.role as PlatformRole) ?? 0
}

/** 店方：维修业务员或超管 */
export function isStoreStaff(): boolean { return platformRole() >= 1 }
/** 超管 */
export function isSuperAdmin(): boolean { return platformRole() === 2 }

/** 本人担任“单位审核员”且已通过的单位 */
export function reviewerEnterprises(): { enterprise_id: string; enterprise_name: string }[] {
  return (useUserStore().userInfo?.enterprises ?? [])
    .filter(e => e.status === 'approved' && (e.role === 'reviewer' || e.role === 'admin'))
    .map(e => ({ enterprise_id: e.enterprise_id, enterprise_name: e.enterprise_name }))
}
/** 是否具备审核员身份（任一已通过单位） */
export function isUnitReviewer(): boolean { return reviewerEnterprises().length > 0 }
/** 是否在某单位内担任审核员 */
export function isReviewerOf(enterpriseId: string): boolean {
  return reviewerEnterprises().some(e => e.enterprise_id === enterpriseId)
}
```

### 2.3 登录态校验与“静默续期”（问题 2 核心）

**目标**：已注册老用户再次进入小程序需要登录的页面时**无感续期**，避免“每次都要点一次登录 / 弹登录页”。

```
页面 onShow（需登录页面的统一守卫）
  └─ 本地有 token？
       ├─ 无 → 静默尝试 wx.login → POST /auth/login
       │        ├─ 成功(need_profile=false) → 写 token → 放行加载数据
       │        ├─ need_profile=true（从未注册）→ 引导去 /pages/auth/login（注册）
       │        └─ 失败（网络）→ 保持“未登录空态 + 去登录按钮”或弹 Modal（按页面场景）
       └─ 有 → 正常请求；若请求返回 401
                 └─ 清 token 前先静默续期一次（同上 wx.login 换新 token）
                      ├─ 成功 → 重放原请求
                      └─ 失败 → 清本地登录态 → Toast“登录已过期，请重新登录” → reLaunch 登录页
```

```typescript
// stores/user.ts（新增 action）
/** 静默续期：本地无 token 或失效时用 wx.login 换新 token；成功返回 true */
async ensureLoggedIn(): Promise<boolean> {
  if (this.token) return true            // 有 token，交由请求层 401 兜底
  try {
    const code = await new Promise<string>((resolve, reject) =>
      uni.login({ provider: 'weixin', success: r => resolve(r.code), fail: reject }))
    const data = await http.post<LoginResult>('/auth/login', { code })
    if (data.need_profile || !data.user) return false   // 全新 openid 需注册
    this.token = data.access_token
    this.userInfo = data.user
    this.isLoggedIn = true
    uni.setStorageSync('token', this.token)
    useEnterpriseStore().syncFromUserInfo(data.user.enterprises)
    return true
  } catch (e) {
    return false
  }
}
```

```typescript
// utils/request.ts（401 兜底改为先静默续期一次再重放）
// 伪代码：在现有 401 分支前增加

  const userStore = useUserStore()
  const ok = await userStore.ensureLoggedIn()      // 注意：本函数内请求不能再走本 request，避免死循环
  if (ok) { /* 用新 token 重放 options */ return }
  /* 原清理登录态 + 跳登录页逻辑 */

```

>
> 决策记录：静默续期仅在“需要登录的操作/页面”时触发（维持延迟登录策略）；协议勾选只属于首次注册，老用户续期不再要求。

onCategoryChange(v: number) {

onProblemPick(p: ProblemOption) {
